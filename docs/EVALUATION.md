# 实验定义与验收

## 固定实验

数据版本 `recjev-v0.1-catalog1-rubric1`。48 个原创合成商品；4 个场景，每个取预设预算的 45%、70%、100%，共 12 个案例。每个案例运行一次召回 / 评分，同时产生逐件贪心和 beam search 两种结果。二者都限制最多 4 件、总价不超预算；组合内部都按同一单品分排序，避免任意排列干扰 NDCG。

- **需求覆盖**：推荐集合覆盖的目标类别数 / 场景目标类别总数（4）。
- **预算满足率**：总价 ≤ 预算的案例占比。
- **NDCG@4**：标签是 `server/evaluation.ts` 中独立手工设定的 0–3 级。DCG 增益为 `2^r - 1`，位置折扣为 `log2(i+2)`；理想列表来自单件价格可负担的全目录，截断为 4。它不是预算组合最优解归一化指标。
- **合成效用**：`0.5 × (sum(label/3)/4) + 0.5 × coverage`。此公式明显偏向覆盖，只能用于演示，不可用于宣称线上满意度提升。
- **区间**：对 12 个案例的效用均值做 500 次 bootstrap，取近似 2.5% 和 97.5% 分位点。数据非随机抽样，区间不能外推真实用户群体。
- **延迟**：两策略共享同次请求的服务端端到端延迟，包含召回、评分、两种组合求解；不是独立策略的耗时对照，不含浏览器渲染 / 网络传输。真实 Jev 时另有模型调用延迟。
- **种子**：只控制 bootstrap 重采样，案例、商品、评分规则都固定。真实云模型不保证可由种子复现。

运行 `npm run evaluate` 输出报告；`docs/baseline-results.json` 保存规则基线的原始运行结果和逐案例商品 ID。无外部 LLM 参与标注或评判。

## 评分与约束

BM25 使用英文词 / 中文双字切分，加入轻量场景加分召回最多 24 件。规则基线依据词法命中、商品所属场景、质量分和反馈标签相似度计算分数；它不具备完整自然语言否定、数字抽取或泛化能力。预算以控制区的数值为准，文本中的“预算 N 元”不会自动覆盖滑块。未知意图回退所选场景并显示提示。

真实 Jev 每个候选使用 Noul 相关性、三档 Score 偏好（冲突 / 中性 / 契合）；Score 的区间为 0–2，除以 2 转为统一范围，confidence 单独保留。模型返回全部合法后才生成方案；缺失、越界、不一致概率分布直接报错。

单品分：`0.68 × relevance + 0.22 × affinity + 0.10 × quality`。

组合目标：`sum(single_score) + diversity × (0.8 × covered_roles − 0.65 × duplicate_categories)`。保留宽度 40 的 beam，最多 4 件，硬性检查总预算与固定 / 排除约束。不是全局最优求解器，不应声称保证最优。固定商品允许不满足通常相关性阈值，以尊重显式选择；其总价格超过预算则拒绝。

广告位与购物组合分开。相关性至少 0.55；不显示已在组合里的商品。合成 pCTR = `0.025 + 0.035 × quality`，竞价分 = `bid × pCTR × ((1−adWeight) × relevance + adWeight)`。单广告位按下一个合格竞价分除以赢家质量因子计价，最低 0.05 元，最高不超过赢家出价。它是简化 GSP 演示，没有真实点击、频控、预算消耗或转化归因。

## 自动验收

`npm test` 的 16 组测试覆盖核心约束与四种模型协议：

1. 4 场景 × 7 档预算下的价格、排除、去重与最大件数。
2. 固定商品保留、超预算与互斥反馈。
3. 未知商品、数值字符串、NaN、非法权重与引擎。
4. 喜欢反馈影响评分，未连接的 Jev 不回退伪造成绩。
5. 相同候选下两种组合策略行为不同。
6. 赞助相关性、独立位置、CPC 上限与关闭行为。
7. 官方协议的问题 ID、候选索引、0 起始 Score、缺失 / 非法分布。
8. 返回模型与 usage 追踪，网络错误不静默降级。
9. 未知意图提示、极小预算的空结果。
10. 固定 cutoff 的 NDCG、逐案例输出、bootstrap 复现。

另外 6 组覆盖通用分数校验、连接地址边界、OpenAI / Claude / MiniCPM 三种请求协议，以及上游错误不回显响应正文。

Jev 合约使用测试夹具，没有真实 Key 调用。真实授权服务效果属于未完成的外部验证。

## 手动界面验收

实际浏览器中验证：首次生成、喜欢反馈、换一件、推荐依据弹窗、固定商品、对照实验；另检查候选筛选、错误状态与连接设置。视口检查记录见 `responsive-checks.json`。记录实际 CSS viewport / client 宽度，不把设定的设备宽度误当 CSS 宽度。最新检查包括 320、390、768、1024、1440 CSS px 的发现页，以及 320、390、768 px 的实验结果和窄屏弹窗；另在 130% 浏览器缩放下检查过有效宽度 246、300、590、984 px。

布局策略：宽屏完整侧栏 + 四列商品；中等宽度压缩侧栏；手机顶部导航 + 两列商品；极窄有效宽度（≤ 340 CSS px）单列。表格在自身容器内滚动，页面不通过 `overflow-x:hidden` 隐藏问题。移动端文本输入采用 16px，避免 iOS 聚焦输入时不必要的自动放大；viewport 不禁止用户缩放。

当前服务为本机单用户演示，没有独立用户登录和多实例共享存储；多个标签页共享 API Key / 运行锁，但各自有前端购物状态。真正公开部署需要先补认证、服务端会话隔离、配额和 TLS。

## 模型间对照

网页的模型对照固定当前 Config，按相同召回逻辑依次执行各路，分别计时。它是单案例探索，不提供跨模型总体胜负。普通 JSON 自评分和本地条件 softmax 不具备 Jev 的相同数值语义，组合规则统一但概率不能横向当作校准置信度。MiniCPM 已有真实权重的读出与完整 24 候选记录，方法与结果见 [模型指南](MODELS.md)；云端 Jev / GPT / Claude 仍需授权 Key 实测。
